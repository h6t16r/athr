# أثر طيب — دليل التشغيل والنشر (للمبتدئين)

**ذكراهم باقية بالدعاء.** موقع Next.js + TypeScript + Tailwind + Prisma + PostgreSQL، مجهّز للنشر على Netlify مع Supabase.

> ⚠️ **تنبيه صريح:** كُتب هذا المشروع في بيئة بلا إنترنت، فلم يُشغَّل ولم تُختبر وظائفه بعد. أول تشغيل قد يُظهر أخطاء بسيطة في البناء أو الكتابة؛ أرسلها لـ Claude وستُصلَّح. لا تعتبر أي ميزة مكتملة قبل تجربتها بنفسك بقائمة الفحص في آخر هذا الملف.

> **تحديث:** رسائل الخطأ في كل النماذج تظهر الآن بالعربي، والصور تُصغَّر تلقائيًا في المتصفح قبل الرفع (حتى 1600px)، وتم تعطيل إيقاف البناء بسبب تحذيرات TypeScript حتى لا يتعطل أول نشر (الأخطاء الفعلية ستظهر وقت التشغيل).

## الخطوة 1: Supabase (قاعدة البيانات والصور)
1. أنشئ حسابًا على supabase.com ثم **New project** (اختر كلمة مرور قوية للقاعدة واحفظها).
2. من **Project Settings → Database → Connection string** انسخ:
   - **Transaction pooler** (منفذ 6543) ← هذا `DATABASE_URL` وأضف في آخره `?pgbouncer=true&connection_limit=1`
   - **Session/Direct** (منفذ 5432) ← هذا `DIRECT_URL`
3. من **Storage** أنشئ Bucketين:
   - `deceased` ← فعّل **Public bucket**
   - `submissions` ← **اتركه Private** (صور الطلبات قبل الموافقة)
4. من **Project Settings → API** انسخ `Project URL` (= `SUPABASE_URL`) و`service_role` (= `SUPABASE_SERVICE_ROLE_KEY`). **سري جدًا، لا تنشره ولا تضعه في GitHub.**

## الخطوة 2: GitHub
1. أنشئ حسابًا ثم **New repository** باسم `athar-tayeb` (اجعله **Private**).
2. اضغط **uploading an existing file** وارفع **محتويات** المجلد (بدون .env ولا node_modules) ثم **Commit**.

## الخطوة 3: Netlify
1. **Add new site → Import from Git** واختر المستودع.
2. قبل أول Deploy: **Site configuration → Environment variables** وأضف كل متغيرات `.env.example` بقيمها الحقيقية:
   `DATABASE_URL, DIRECT_URL, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, SUPABASE_PUBLIC_BUCKET, SUPABASE_PRIVATE_BUCKET, AUTH_SECRET, SETUP_TOKEN, ADMIN1/2/3_USERNAME/NAME/PASSWORD, NEXT_PUBLIC_SITE_URL`
   - `AUTH_SECRET` و`SETUP_TOKEN`: نصوص عشوائية طويلة (استخدم مولد كلمات مرور).
   - كلمات مرور الإدارة: **12 حرفًا فأكثر**.
3. اضغط **Deploy**. أثناء البناء تُنشأ الجداول تلقائيًا (`prisma db push`).

## الخطوة 4: إنشاء الحسابات الإدارية الثلاثة (مرة واحدة)
افتح في المتصفح:
`https://موقعك.netlify.app/api/setup?token=قيمة_SETUP_TOKEN`
- يظهر `ok: true` ← أُنشئت 3 حسابات (الأول رئيسي) + المحافظات + أسماء السور.
- الرابط **لا يعمل بعدها أبدًا** (يرجع 404 بمجرد وجود حساب إداري).
- بعدها **احذف** `SETUP_TOKEN` و`ADMIN*_PASSWORD` من Netlify، ثم ادخل `/admin/login` وغيّر كلمات المرور.

## الخطوة 5: ضبط المحتوى من لوحة التحكم
- **المواقع:** أضف المراكز والقرى (المحافظات الـ27 مضافة).
- **القراء والصوت:** أضف قارئًا ثم روابط https لتلاوات **مرخّصة/رسمية** لكل سورة. لم نُضف أي روابط من عندنا.
- **الآيات والأحاديث:** أضف نصوصًا موثّقة مع المصدر ودرجة الصحة. لا تُضف ما لم تتأكد منه.
- **الإعدادات:** تحكم في معدل ظهور النوافذ المنبثقة (الحد الأدنى 30 ثانية).

## النسخ الاحتياطي
- Supabase يحتفظ بنسخ تلقائية يومية (حسب الخطة). فعّل من **Database → Backups**، ويفضّل خطة تدعم PITR للمشاريع الجادة.
- نزّل نسخة يدوية دوريًا من **Database → Backups** أو أمر `pg_dump`.

## التشغيل على جهازك (اختياري للمطورين)
```
cp .env.example .env   # املأه
npm install
npx prisma db push
npm run dev
# ثم افتح /api/setup?token=...
```
للانتقال إلى Migrations رسمية لاحقًا: `npx prisma migrate dev --name init` ثم غيّر أمر البناء في package.json إلى `prisma migrate deploy`.

## كيف طُبّقت الشروط
- 3 حسابات إدارية فقط، بلا تسجيل للزوار، والصلاحيات تُفحص في **الخادم** داخل كل Server Action وكل صفحة إدارية (وليس بإخفاء الأزرار).
- كلمات المرور مشفّرة bcrypt. الجلسة JWT في كوكي HttpOnly، وحماية من تكرار محاولات الدخول.
- صور طلبات الأسر في Bucket **خاص** ولا تنتقل للعام إلا بعد موافقة الإدارة. بيانات مقدم الطلب لا تظهر في أي صفحة عامة.
- التحقق من الصور بمحتوى الملف (JPG/PNG/WEBP) وحجم أقصاه 5MB. حقول فخ للروبوتات + حدّ للمحاولات.
- مشغل القرآن: مصدر صوت واحد، يبدأ بضغطة الزائر، ويتوقف عند مغادرة الصفحة. النوافذ المنبثقة لا تظهر أثناء التشغيل.
- لا إعجابات ولا ترتيب للمتوفين.
